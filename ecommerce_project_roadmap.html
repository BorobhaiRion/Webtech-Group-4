Branch strategy (since you're new to Git collaboration)

Simple 2-branch approach — no complex rebasing needed for a 3–4 hour exam.
git checkout -b feature/auth-backend   # BE1
git checkout -b feature/product-backend  # BE2
git checkout -b feature/auth-ui         # FE1
git checkout -b feature/cart-ui         # FE2
1. BE1 creates the repo and pushes the initial folder structure to main
2. Everyone else clones: git clone <url>
3. Each person creates their own branch and works only in their own files
4. Commit often — every completed function/form is a commit
5. At Phase 3 start: each person pushes, then one person merges all into main
6. Everyone pulls main and continues on their branch

Files each person owns (no overlap = no merge conflicts)

Agree on this before starting to avoid conflicts.
